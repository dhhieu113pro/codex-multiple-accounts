# Codex Multiple Accounts v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a cross-platform Avalonia desktop app that manages multiple Codex CLI profiles, runs isolated profiles concurrently via `CODEX_HOME`, and optionally activates one profile into the default Codex home.

**Architecture:** A .NET 10 solution separates profile/filesystem/process logic into `CodexMultipleAccounts.Core` and presentation/platform integration into `CodexMultipleAccounts.App`. The app uses an `ITerminalSession` abstraction so Windows can use a Dev Board-style PTY/native host while all platforms retain an external-terminal launcher fallback.

**Tech Stack:** .NET 10, Avalonia 11, CommunityToolkit.Mvvm, System.Text.Json, xUnit, Microsoft.NET.Test.Sdk, coverlet collector, Porta.Pty for PTY support, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-06-codex-multiple-accounts-design.md`

## Global Constraints

- Support Windows, Linux, and macOS.
- Isolated launches set `CODEX_HOME` only on the child process.
- Global activation is explicit and creates a recoverable backup before replacement.
- Never log or transform authentication contents.
- Profile paths must be validated before recursive copy/delete operations.
- Embedded terminal support must remain behind a platform-neutral abstraction.
- Core tests run on Windows, Linux, and macOS CI.
